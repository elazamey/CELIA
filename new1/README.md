# NEW1 — مساحة وكلاء AI محلية ومجانية

**NEW1** نواة مفتوحة المصدر لبناء مساعد عام ينفّذ المهام على ملفاتك، بدل الاكتفاء بالمحادثة. يعمل افتراضيًا مع **Ollama** ونماذج محلية، ويستخدم **[stablyai/orca](https://github.com/stablyai/orca)** كطبقة اختيارية لتنسيق الوكلاء وتطبيق سطح المكتب ومسارات `git worktree`.

> لا اشتراك، لا مفتاح API، ولا خادم AI مدفوع في المسار الافتراضي. جودة النتائج تعتمد على النموذج والعتاد، ولا يعني اسم المشروع أو ربط Orca أنه يتفوق تلقائيًا على Claude أو Manus.

## ما الذي يعمل الآن؟

- **وكيل واحد أو فريق محلي**: مخطط، منفّذ، ومراجع في وضع `team` باستخدام النموذج المحلي نفسه أو أي نموذج تختاره.
- **أدوات حقيقية للملفات**: قراءة، كتابة، سرد، وبحث داخل `workspace/` فقط.
- **اختبارات اختيارية**: عند تفعيلها للمهمة، لا يتوفر للنموذج سوى أمر `npm test` — وليس Shell مفتوحًا.
- **سجل محلي وحي**: حفظ المهام في `.data/tasks.json` وبث حالتها لحظيًا عبر SSE.
- **واجهة عربية RTL**: قائمة مهام، تفاصيل التنفيذ، مستعرض ملفات، حالة Ollama، وإعدادات التكامل.
- **بدون اعتماديات تشغيل خارجية**: نواة NEW1 تحتاج Node.js 22+ فقط؛ Ollama منفصل.
- **تكامل Orca قابل للتكرار**: مصدر مثبت بمراجعة Git محددة في `orca.source.json` وملف `orca.yaml` لمسارات العمل.

## التشغيل السريع

### 1. المتطلبات

- [Node.js 22+](https://nodejs.org/)
- [Ollama](https://ollama.com/) يعمل على جهازك
- ذاكرة مناسبة للنموذج الذي تختاره

### 2. نزّل نموذجًا وشغّل Ollama

```bash
ollama pull qwen3:8b
ollama serve
```

يمكنك استخدام أي نموذج آخر يدعم المحادثة؛ وللحصول على أفضل استخدام للأدوات اختر نموذجًا يدعم **tool calling** في Ollama.

### 3. شغّل NEW1

```bash
cp .env.example .env       # اختياري؛ القيم الافتراضية تعمل
npm run setup
npm start
```

افتح `http://localhost:3000`. لا حاجة إلى `npm install` لنواة NEW1 لأنها لا تستخدم حزم npm خارجية.

### Docker (اختياري)

```bash
docker compose up --build -d
docker compose exec ollama ollama pull qwen3:8b
```

ثم افتح المنفذ `3000`. تُحفظ النماذج والمهام وملفات مساحة العمل في Docker volumes مستقلة (`ollama-models` و`new1-data` و`new1-workspace`).

## استخدام Orca

Orca ليس بديلًا للنموذج؛ إنه طبقة تشغيل وتنسيق. لجلب المصدر الرسمي عند المراجعة المثبتة:

```bash
npm run orca:init
```

يُحفظ في `vendor/orca/` ولا يدخل ضمن حزمة NEW1 أو Docker. مشروع Orca نفسه يستخدم **Node.js 24 وpnpm** وله اعتماديات وتعليمات مستقلة؛ راجع `vendor/orca/AGENTS.md` و`vendor/orca/README.md` قبل تطويره.

يمكن فتح جذر NEW1 في Orca للاستفادة من `orca.yaml`: تبويب للوكيل، وتبويب للواجهة المحلية، وتبويب للتحقق. بهذا يمكن تشغيل عدة مسارات تطوير معزولة بينما تبقى نواة NEW1 المحلية مستقلة عن أي اشتراك.

## كيف ينفّذ الوكيل مهمة؟

1. ترسل الواجهة الوصف إلى `POST /api/tasks`.
2. يُنشئ المخطط خطة قصيرة إذا اخترت وضع الفريق.
3. يستدعي المنفّذ Ollama مع مخططات الأدوات المسموحة.
4. تنفّذ نواة NEW1 الأداة داخل حدود مساحة العمل، ثم تعيد ناتجها للنموذج.
5. يحفظ السجل كل حدث محليًا ويرسل التحديث إلى الواجهة.
6. يضيف المراجع إجابة نهائية في وضع الفريق، دون ادعاء اختبارات لم تُنفّذ.

تفاصيل أكثر في [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## حدود الأمان

| المورد | الوضع الافتراضي |
|---|---|
| قراءة/كتابة الملفات | داخل `workspace/` فقط |
| `.git` و`.env` | محجوبان عن أدوات الوكيل |
| الروابط الرمزية | مرفوضة لمنع الخروج من مساحة العمل |
| حجم الملف النصي | 200 KB للقراءة أو الكتابة عبر الأداة |
| تنفيذ الأوامر | غير متاح افتراضيًا |
| `npm test` | متاح فقط عند تفعيله لكل مهمة |
| مزود النموذج | Ollama محلي فقط في النواة |

**مهم:** تشغيل نموذج محلي لا يجعل الكود الناتج آمنًا تلقائيًا. راجع التغييرات والاختبارات قبل تشغيل مشروع مكتوب بالوكيل. لا تضع أسرار الإنتاج في مساحة العمل. وقد تنفّذ `npm test` أي كود موجود في `package.json`؛ فعّلها فقط لمشروع موثوق، فهي ليست حاوية أمان.

## الإعدادات

انسخ `.env.example` إلى `.env` وغيّر ما يلزم:

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | عنوان خادم Ollama الذي يتصل به **الخادم** |
| `OLLAMA_MODEL` | `qwen3:8b` | النموذج الافتراضي |
| `PORT` | `3000` | منفذ واجهة NEW1 |
| `NEW1_MAX_STEPS` | `10` | حد دورات النموذج والأدوات للمنفّذ |
| `NEW1_MAX_CONCURRENCY` | `2` | عدد المهام المتزامنة |
| `NEW1_WORKSPACE_DIR` | `./workspace` | جذر ملفات الوكيل |
| `NEW1_DATA_DIR` | `./.data` | سجل المهام المحلي |

## التطوير والتحقق

```bash
npm run check       # فحص صياغة ملفات JavaScript
npm test            # اختبارات Node.js دون Ollama
npm run validate    # كل البوابات المحلية
```

الاختبارات تستخدم مزودًا وهميًا، لذلك لا تحتاج إلى تنزيل نموذج ولا تدّعي اختبار جودة نموذج حقيقي.

```text
new1/
├── public/               # واجهة عربية بلا إطار عمل
├── src/
│   ├── agent.mjs         # حلقة الوكيل ووضع الفريق
│   ├── provider.mjs      # Ollama فقط
│   ├── tools.mjs         # أدوات مساحة العمل وحدودها
│   ├── task-manager.mjs  # الطابور والإلغاء والتحديثات
│   ├── store.mjs         # تخزين JSON ذري محليًا
│   └── server.mjs        # HTTP + SSE + الملفات الثابتة
├── scripts/orca-sync.mjs # جلب Orca بمراجعة مثبتة
├── tests/                # اختبارات النواة والتكامل
├── docs/                 # المعمارية وخارطة الطريق
├── compose.yaml          # NEW1 + Ollama
└── orca.yaml             # ملف مساحة عمل Orca
```

## ما معنى «مجاني بالكامل» هنا؟

الكود MIT ولا يفرض NEW1 رسومًا أو حسابًا أو API مدفوعًا. لكن العتاد والكهرباء ليسا مجانيين، وقد تكون لأوزان النماذج تراخيص منفصلة. راجع ترخيص كل نموذج قبل الاستخدام التجاري. لا يمنع المشروع مطوّره من إضافة مزودين آخرين، لكن النواة الحالية لا تتضمنهم.
