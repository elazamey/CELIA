# معمارية NEW1

## الهدف

نواة صغيرة يمكن فهمها وتعديلها، تفصل بين واجهة المستخدم، إدارة المهام، مزود النموذج، وتنفيذ الأدوات. لا يحتاج تشغيل الاختبارات إلى نموذج أو شبكة.

## المكونات

```text
Browser (Arabic RTL)
       │ same-origin HTTP + SSE
       ▼
src/server.mjs
       ├── TaskManager ── TaskStore (.data/tasks.json)
       │        │
       │        └── Agent loop ── OllamaProvider ── local Ollama
       │                  │
       │                  └── WorkspaceTools ── workspace/
       └── Static files / workspace read API

vendor/orca (optional, independently fetched)
       └── Desktop UI and isolated development worktrees
```

## دورة المهمة

- الحالات: `queued → running → completed | failed | cancelled`.
- يحتفظ `TaskManager` بعداد مهام نشطة ويحد التزامن لتجنب إغراق خادم النموذج.
- كل تحديث يُحفظ أولًا ثم يُبث إلى عملاء SSE.
- عند إعادة تشغيل الخادم تُعلّم المهام غير المنتهية كفاشلة بوضوح؛ لا يدّعي النظام استئناف سياق فقده.
- الإلغاء يستخدم `AbortController` ويمرر الإشارة إلى طلب Ollama.

## وضع الفريق

يستخدم ثلاث رسائل نظام متخصصة، لا ثلاث خدمات مدفوعة:

1. **المخطط**: حتى ست خطوات عملية، دون أدوات.
2. **المنفّذ**: حلقة نموذج/أدوات بحد أقصى للخطوات.
3. **المراجع**: مقارنة موجزة بالطلب الأصلي والنتيجة، دون القدرة على اختلاق تشغيل أدوات.

يمكن لاحقًا استبدال كل دور بمزود أو نموذج مختلف عبر واجهة `provider.chat` نفسها.

## عقد مزود النموذج

```js
provider.health()
provider.listModels()
provider.chat({ model, messages, tools, signal })
```

النواة الحالية تضم `OllamaProvider` فقط. الاختبارات تمرر كائنًا وهميًا بالعقد نفسه. أي مزود جديد يجب أن يكون اختياريًا وصريحًا، وألا يغير وصف المسار المحلي المجاني.

## التخزين

`TaskStore` ليس قاعدة بيانات موزعة؛ إنه مخزن JSON محلي متعمد للبساطة. الكتابة تتم إلى ملف مؤقت ثم `rename` لتقليل خطر ملف نصف مكتوب. عند الحاجة إلى عدة نسخ خادم أو مستخدمين، يجب استبداله بقاعدة بيانات مع معاملات ومصادقة، لا تعديل JSON ليكون خادمًا موزعًا.

## حدود الأدوات

- جميع المسارات نسبية إلى جذر مساحة العمل.
- فحص المسار النصي ثم الحقيقي (`realpath`) لمنع `../` والخروج عبر الروابط.
- حجب `.git` و`.env` والروابط الرمزية و`node_modules`.
- حدود لحجم الملفات وعدد النتائج وعمق البحث.
- لا توجد أداة Shell عامة. `run_tests` ينفذ `npm test` فقط بـ `shell:false` وبيئة مختصرة ومهلة.

هذه حدود دفاعية وليست بديلًا عن حاوية أو مستخدم نظام منفصل عند تشغيل كود غير موثوق.

## الأسرار والشبكة

لا تحتاج النواة إلى أسرار. الواجهة تستدعي مسارات نسبية فقط؛ عنوان Ollama يستخدمه خادم Node وليس المتصفح. لا يوجد CORS مفتوح ولا وكيل إنترنت عام. نشر الواجهة على الإنترنت كما هي غير موصى به قبل إضافة مصادقة وتشفير وعزل أقوى.

## Orca

يحتفظ `orca.source.json` بعنوان المصدر ومراجعة Git. ينزّل `scripts/orca-sync.mjs` تلك المراجعة في checkout منفصل، لذلك لا تُنسخ اعتماديات Orca الضخمة إلى نواة NEW1. ملف `orca.yaml` يعرّف تهيئة وتبويبات المشروع عند فتحه في Orca.
